# anti-scan-govno

**Меньше сканеров на сервере. Меньше лишнего трафика через ноды.**

Защита на уровне nftables для серверов с Xray: блокировка IP-адресов основных сканеров РКН, ГРЧЦ, СКИПА и VK, а также опциональная блокировка исходящих IP-сетей VK, MAX и OK.

## Что умеет

| Возможность | Как работает |
|---|---|
| **Защита от сканеров** | Блокирует пакеты из списков C24Be и AntiScanner до Xray и TLS. Работает для IPv4 и IPv6, всех портов и ICMP. |
| **Блокировка VK на нодах** | По флагу блокирует исходящие соединения к IP-сетям VK, MAX и Одноклассников. |
| **Списки исключений** | Пропускает указанные IPv4- и IPv6-адреса до проверки блок-листа. |
| **Обновление без простоев** | Ежедневно загружает списки и заменяет правила одной транзакцией. |
| **Пробный запуск** | Сначала проверяет списки без изменения правил — `DRY_RUN=true` по умолчанию. |
| **Простое управление** | Устанавливается интерактивным скриптом или через Docker Compose; отдельный скрипт удаляет сервис. |

> [!IMPORTANT]
> До включения правил добавьте свой управляющий IP в allowlist, если он может попасть в блок-лист. Это поможет сохранить доступ по SSH и WG.

## Что блокируется

### Входящие подключения

На всех серверах блокируются входящие пакеты с IP-адресов из списков C24Be и AntiScanner. В них входят сети **РКН, ФСБ, МВД, ГРЧЦ, ESPD, CyberOK/SKIPA и Nessly (VK)**, а также сканеров Censys, Shodan, Shadowserver, Rapid7, Xpanse, ONYPHE, LeakIX, Driftnet, Recyber, FOFA, ZoomEye, Quake, Netlas, Group-IB и Criminal IP.

Для новых входящих подключений блокировка действует на все порты и протоколы, в том числе ICMP: обычный `ping` с заблокированного адреса не получит ответа. Уже установленные соединения, loopback и адреса из allowlist пропускаются до проверки блок-листа.

### Исходящие подключения

На зарубежных нодах можно включить блокировку исходящих соединений к **IP-сетям VK, MAX и Одноклассников (OK)** из списка C24Be. Для этого установите `ENABLE_VK_OUTPUT=true`; на транзитном сервере оставьте `false`.

Это IP-подстраховка для правил Xray: сервис не блокирует домены и не меняет настройки Xray. Исходящие соединения к адресам из VK-списка блокируются целиком, включая другие сервисы на общих IP-адресах. Уже установленные соединения пропускаются.

Блокируются адреса и сети, содержащиеся в загруженных списках; их состав может изменяться у авторов.

## Установка

### Требования

Требуются Linux, Docker с Compose plugin, `curl` и права root. Docker с `host` networking и `NET_ADMIN` должен управлять сетевым пространством защищаемого Linux-хоста. Docker Desktop работает в отдельной виртуальной машине и не защищает сам macOS/Windows-хост. В ядре нужны nftables и conntrack.

### Интерактивный установщик

Запустите:

```sh
sudo sh -c "$(curl -fsSL https://raw.githubusercontent.com/theillarion/anti-scan-govno/master/install.sh)"
```

Установщик спросит каталог, роль сервера, адреса исключений и режим пробного запуска. Он скачает готовый образ `ghcr.io/theillarion/anti-scan-govno:latest`, без сборки на сервере. По умолчанию используется `/opt/nftguard` и включён `DRY_RUN=true`. Для установки без входа в GHCR пакет должен быть публичным.

При повторном запуске укажите существующий каталог установки. Установщик проверит образ в GHCR: если он не изменился, контейнер останется как есть; если образ отличается, установщик попросит подтвердить обновление. `.env`, `compose.yaml` и `state/` сохраняются; для старой стандартной конфигурации после подтверждения добавляется право `DAC_OVERRIDE`, необходимое для записи в каталог пользователя. Обновляется образ с тегом, заданным в Compose и `.env`; при закреплённой версии переход на другую версию сначала нужно указать в настройках. Проверка скачивает образ, но до подтверждения контейнер не останавливает. Установки со сборкой из исходников этот механизм не изменяет.

После установки проверьте журнал:

```sh
cd /opt/nftguard
docker compose logs -f
```

Затем установите `DRY_RUN=false` в `.env` и примените конфигурацию:

```sh
docker compose up -d
```

Если управляющий IP может оказаться в блок-листе, добавьте его в allowlist до включения правил, чтобы сохранить возможность новых SSH/WG-подключений.

### Готовый образ через Docker Compose

Можно установить сервис вручную, не клонируя репозиторий и не собирая образ:

```sh
mkdir -p nftguard/state
cd nftguard
curl -fsSLo compose.yaml https://raw.githubusercontent.com/theillarion/anti-scan-govno/master/compose.ghcr.yaml
curl -fsSLo .env https://raw.githubusercontent.com/theillarion/anti-scan-govno/master/.env.example
# Измените .env для конкретного сервера.
docker compose up -d
docker compose logs -f
```

Для фиксации версии добавьте в `.env` строку `NFTGUARD_IMAGE_TAG=X.Y.Z` вместо используемого по умолчанию `latest`. Обновление образа: `docker compose pull && docker compose up -d`. CI публикует образы для `linux/amd64` и `linux/arm64` по тегу `vX.Y.Z` после успешных тестов; ручной запуск workflow принимает существующий тег. При публикации старого тега метки `X.Y` и `latest` также будут обновлены.

### Docker Compose: сборка из исходников

Для сборки образа из репозитория:

```sh
git clone https://github.com/theillarion/anti-scan-govno.git
cd anti-scan-govno
cp .env.example .env
# Измените .env для конкретного сервера.
docker compose up -d --build
docker compose logs -f
# После проверки измените DRY_RUN на false и выполните:
docker compose up -d
```

## Настройки

Параметры задаются в `.env` рядом с `compose.yaml`.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `NFTGUARD_IMAGE_TAG` | `latest` | Версия готового образа GHCR (только `compose.ghcr.yaml`) |
| `ENABLE_VK_OUTPUT` | `false` | Блокировка VK/MAX/OK на выходе |
| `UPDATE_AT` | `03:00` | Ежедневное обновление в формате `HH:MM` |
| `TZ` | `Europe/Moscow` | Часовой пояс расписания и логов |
| `ALLOW_CIDRS` | пусто | IPv4-адреса или CIDR через запятую или пробел |
| `ALLOW_CIDRS6` | пусто | IPv6-адреса или CIDR через запятую или пробел |
| `DRY_RUN` | `true` | Загружать и проверять списки, не меняя nftables |
| `BOOT_DELAY_SECONDS` | `120` | Время после загрузки Linux в секундах до применения правил; `0` отключает задержку |
| `HTTP_TIMEOUT` | `30s` | Таймаут запроса; поддерживаются `s`, `ms` и `m` |
| `RETRIES` | `3` | Число повторов после первой попытки |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

После загрузки Linux сервис откладывает восстановление и применение правил до истечения `BOOT_DELAY_SECONDS` от запуска системы. Например, при значении `120` и старте контейнера через 45 секунд ожидание составит ещё 75 секунд. Перезапуск контейнера не сбрасывает отсчёт; если он произошёл уже после окончания окна, задержки нет. Команда `update` также ожидает окончания окна, а `healthcheck` и `DRY_RUN` не ждут. Во время ожидания в журнале появляется `event=boot_delay`; healthcheck может показывать `unhealthy`, пока правила не применены. Значение должно быть неотрицательным целым числом.

Окно позволяет подключиться к серверу и остановить сервис до восстановления правил после перезагрузки. При этом остановка сервиса не удаляет уже действующие правила, а другие средства могут загрузить свои правила раньше. На Linux с Docker отсчёт идёт по времени работы ядра хоста; в Docker Desktop — ядра виртуальной машины. Параметр не заменяет allowlist и не защищает от ошибок других файрволов.

C24Be обновляет данные около 02:30 UTC; `03:00` в Москве соответствует 00:00 UTC. Для более свежего выпуска используйте `UPDATE_AT=06:00` при московском часовом поясе.

## Проверка и управление

Проверить журнал и таблицу правил:

```sh
cd /opt/nftguard
docker compose logs -f
sudo nft list table inet nftguard
```

Пересобрать образ из исходников и перезапустить сервис:

```sh
docker compose up -d --build
```

### Удаление

Полностью удалить сервис, локально собранный образ, правила и каталог установки с настройками и состоянием можно одной командой:

```sh
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/theillarion/anti-scan-govno/master/uninstall.sh)"
```

Или запустите скрипт из каталога установки:

```sh
sudo /opt/nftguard/uninstall.sh
```

Если выбран другой каталог, укажите путь к `uninstall.sh` в нём. Скрипт запросит путь и подтверждение `DELETE`. В клонированном репозитории его можно запустить как `sudo bash ./uninstall.sh` и указать каталог установки. Если скрипт не сможет удалить правила, он сохранит каталог, чтобы удаление можно было повторить. Образ, скачанный из GHCR, остаётся в локальном кэше Docker.

Для ручной остановки без удаления файлов используйте `docker compose down`. Эта команда сама по себе правила не удаляет; чтобы удалить только таблицу nftguard, выполните `sudo nft delete table inet nftguard`. При следующем запуске сервис восстановит правила или загрузит заново.

Состояние хранится в `state/`: `status.json`, `current.nft` и `previous.nft`. При ошибке загрузки обязательных списков существующая таблица остаётся прежней. При недоступном или не прошедшем пороги AntiScanner используется только C24Be. При запуске свежий `current.nft` восстанавливается, если конфигурация совпадает. Изменение allowlist или флага VK вызывает повторную загрузку. Пробный запуск не создаёт `current.nft`; healthcheck в этом режиме проверяет успешность последней загрузки.

Если IPv6-файл C24Be пуст, сервис пишет предупреждение `source=c24_v6 reason=empty_list` и добавляет `c24_v6` в `empty_sources` файла `status.json`. Правила применяются с IPv4-сетями C24Be и доступными сетями AntiScanner. При этом IPv6-сети C24Be в обновлённых правилах отсутствуют; если AntiScanner тоже недоступен, IPv6-блокировки источников не будет. Непустой некорректный файл C24Be считается ошибкой.

## Как это работает

- Правила действуют на входящий и исходящий трафик хоста. Транзитный forwarded-трафик и контейнеры в отдельных сетевых пространствах не покрываются.
- После перезагрузки правила появятся при старте Docker; до этого момента защиты нет.
- Чужие таблицы и их политики не изменяются. Другие правила файрвола могут дополнительно ограничивать трафик, в том числе адреса из allowlist nftguard.
- В `DRY_RUN` сервис не применяет и не удаляет правила. Если таблица уже была создана ранее, она продолжит действовать.

## Тестирование

После клонирования запустите все локальные проверки одной командой:

```sh
./tests/sandbox/run.sh
```

Нужны Docker Engine с Compose и поддержкой IPv6 и nftables. При первой сборке требуется интернет для загрузки образа и тестовых зависимостей. Скрипт собирает отдельный образ, запускает модульные тесты и выводит отчёт совокупного покрытия производственного Python-кода модульными и сетевыми тестами (минимум 95%), проверяет доступ к каталогу состояния без смены его владельца, установщик и удаление, а затем проверяет реальные TCP-соединения IPv4 и IPv6 между контейнерами. Проверяются блокируемые и обычные адреса, allowlist и опциональная исходящая блокировка. Внешние блок-листы для этих проверок не загружаются. Отчёты сохраняются в `coverage-report/`: текстовый, HTML (`html/index.html`), XML и JSON. Процент относится к строкам Python-кода; shell-скрипты проверяются отдельно и в него не входят. GitHub Actions запускает набор при push и pull request, показывает сводку покрытия и прикладывает полный отчёт к запуску.

Контейнеры получают `NET_ADMIN` только в собственных сетевых пространствах; используется внутренняя Docker-сеть, а не сеть хоста. Скрипт удаляет контейнеры и сеть после завершения; образ остаётся в кэше. Для тестовой сети зарезервированы `172.29.241.0/24` и `fd42:6e66:7467::/64`: при пересечении с существующими сетями Docker нужно изменить адреса в `tests/sandbox/compose.yaml`, `peer.py` и `traffic.py` согласованно. Отдельный `tests/integration.py` обращается к настоящим внешним спискам и не входит в этот автономный набор.
